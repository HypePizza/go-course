# Урок 1. Функции: множественный возврат, именованные результаты, вариативные функции

> Модуль 2 «Функции и данные» · Go 1.27.1 · macOS

## Зачем это нужно

До сих пор весь код жил в `main`, и вы уже видели, к чему это ведёт: в `hsize` одна и та же проверка была написана дважды, а «напечатать ошибку и выйти» повторялось пять раз. Функции убирают повторы и дают куску кода имя. А пара `(результат, error)` — самая частая сигнатура в Go: вы встретите её в каждом пакете стандартной библиотеки и в каждом рабочем проекте.

## Объяснение

### Объявление

```go
func add(a int, b int) int {
	return a + b
}

func add2(a, b int) int { // параметры одного типа можно сгруппировать
	return a + b
}
```

Порядок: `func`, имя, параметры, тип результата. Тип пишется **после** имени — как в объявлении переменных.

**Аргументы передаются по значению**, как в C: функция получает копию. Изменить переменную вызывающего кода можно только через указатель — это модуль 3.

Функции объявляются на уровне пакета, и **порядок не важен**: `main` может вызывать функцию, объявленную ниже. Никаких прототипов и заголовочных файлов.

### Множественный возврат

```go
// divmod возвращает частное и остаток — два значения сразу
func divmod(a, b int) (int, int) {
	return a / b, a % b
}

q, r := divmod(17, 5) // 3 2
_, rest := divmod(10, 3) // ненужное значение — в _
```

Главное применение — **результат + ошибка**. Вы уже пользовались этим в `strconv.Atoi`:

```go
// safeDiv возвращает результат и ошибку — главная идиома Go
func safeDiv(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("деление на ноль") // пакет errors
	}
	return a / b, nil // nil — «ошибки нет»
}
```

Правила этой идиомы:
- ошибка — **последний** результат;
- если ошибка не `nil`, остальные результаты обычно не используют — возвращайте нулевые значения;
- если текст ошибки нужно собрать из данных, используйте `fmt.Errorf` — это `Sprintf`, который возвращает `error`:

```go
return 0, fmt.Errorf("%q — не число", s)
```

Подробно про ошибки — в модуле 4. Пока достаточно `errors.New` и `fmt.Errorf`.

### Именованные результаты

```go
// bounds — именованные результаты: lo и hi уже объявлены и равны 0
func bounds(nums ...int) (lo, hi int) {
	if len(nums) == 0 {
		return // «голый» return вернёт текущие lo и hi, то есть 0, 0
	}
	lo, hi = nums[0], nums[0]
	for _, n := range nums {
		if n < lo {
			lo = n
		}
		if n > hi {
			hi = n
		}
	}
	return lo, hi
}
```

Именованные результаты — это обычные переменные, объявленные в начале функции с нулевыми значениями. Они полезны как **документация**: по сигнатуре `(lo, hi int)` сразу понятно, что вернётся, а `(int, int)` ничего не говорит.

«Голый» `return` без значений возвращает текущие значения этих переменных. В коротких функциях это допустимо, в длинных — **не используйте**: читателю приходится искать, что там сейчас лежит. На ревью голый `return` в функции длиннее 5–10 строк обычно просят переписать.

### Вариативные функции

```go
// sum принимает любое количество чисел; внутри функции nums — это слайс []int
func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

sum()         // 0
sum(1, 2, 3)  // 6

nums := []int{4, 8, 15, 16, 23, 42}
sum(nums...)  // 108 — распаковка слайса в аргументы
```

- `...` может стоять только у **последнего** параметра.
- Внутри функции параметр — обычный слайс. Слайсы подробно разберём в уроке 4 этого модуля; пока достаточно `range`, `len` и `append`, которые вы уже использовали.
- `fmt.Println` и `fmt.Printf` — тоже вариативные функции: `func Println(a ...any)`. `any` значит «значение любого типа», подробно — в модуле 4.

### Функция-помощник для ошибок

Вот то, что повторялось в `hsize`, — теперь в одном месте:

```go
// fail печатает ошибку в stderr и завершает программу
func fail(format string, args ...any) {
	fmt.Fprintf(os.Stderr, "ошибка: "+format+"\n", args...)
	os.Exit(1)
}

fail("неожиданный аргумент %q", os.Args[1])
```

`args...` передаёт полученные аргументы дальше в `Fprintf` как есть.

### Полный пример

**`main.go`** (запуск из корня репозитория: `go run ./module2/l1-functions`)

```go
package main

import (
	"errors"
	"fmt"
	"os"
)

// divmod возвращает частное и остаток — два значения сразу
func divmod(a, b int) (int, int) {
	return a / b, a % b
}

// safeDiv возвращает результат и ошибку — главная идиома Go
func safeDiv(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("деление на ноль")
	}
	return a / b, nil
}

// sum принимает любое количество чисел; внутри функции nums — это слайс []int
func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

// bounds — именованные результаты: lo и hi уже объявлены и равны 0
func bounds(nums ...int) (lo, hi int) {
	if len(nums) == 0 {
		return // «голый» return вернёт текущие lo и hi, то есть 0, 0
	}
	lo, hi = nums[0], nums[0]
	for _, n := range nums {
		if n < lo {
			lo = n
		}
		if n > hi {
			hi = n
		}
	}
	return lo, hi
}

// fail печатает ошибку в stderr и завершает программу
func fail(format string, args ...any) {
	fmt.Fprintf(os.Stderr, "ошибка: "+format+"\n", args...)
	os.Exit(1)
}

func main() {
	q, r := divmod(17, 5)
	fmt.Println(q, r)

	if res, err := safeDiv(10, 0); err != nil {
		fmt.Println("не получилось:", err)
	} else {
		fmt.Println(res)
	}

	fmt.Println(sum(), sum(1, 2, 3))
	nums := []int{4, 8, 15, 16, 23, 42}
	fmt.Println(sum(nums...)) // распаковка слайса в аргументы

	lo, hi := bounds(nums...)
	fmt.Println(lo, hi)

	_, rest := divmod(10, 3) // ненужное значение отбрасываем через _
	fmt.Println(rest)

	if len(os.Args) > 1 {
		fail("неожиданный аргумент %q", os.Args[1])
	}
}
```

Вывод:

```
3 2
не получилось: деление на ноль
0 6
108
4 42
1
```

С аргументом (`go run ./module2/l1-functions xyz`) добавится `ошибка: неожиданный аргумент "xyz"` в stderr и код выхода `1`.

## Сравнение с C и Python

| | C | Python | Go |
|---|---|---|---|
| Несколько результатов | один; остальные — через указатели (`out`-параметры) | `return a, b` — кортеж | `return a, b` — **не кортеж**: в одну переменную не положить |
| Ошибки | код возврата + `errno` | исключения | `error` последним результатом |
| Значения по умолчанию | нет | `def f(x=1)` | **нет** |
| Именованные аргументы при вызове | нет | `f(x=1)` | **нет** |
| Перегрузка (одно имя, разные параметры) | нет | нет | **нет** |
| Переменное число аргументов | `...` + `va_list`, без типов | `*args` | `...T` — типизированный слайс |
| Объявление до использования | нужен прототип | функция должна быть определена к моменту вызова | порядок не важен |

Привычки, которые будут мешать:
- **Из Python:** искать значения по умолчанию и `**kwargs`. В Go для этого делают несколько функций с разными именами или передают структуру с настройками (модуль 3).
- **Из Python:** «пусть упадёт с исключением, поймаю выше». В Go ошибку возвращают явно, и вызывающий код **обязан** решить, что с ней делать.
- **Из C:** возвращать `-1` как признак ошибки. В Go для этого есть отдельный результат `error`.

## Типичные ошибки

1. **Взять один результат из двух.** `n := strconv.Atoi("5")` — ошибка компиляции `assignment mismatch`. Нужно `n, err := ...` или явно `n, _ := ...`.
2. **Отбросить ошибку через `_` «пока что».** Компилятор доволен, а программа молча работает с нулевым значением. Пишите `_` для ошибки, только если точно знаете, что её не бывает, — и оставьте комментарий почему.
3. **Забыть `...` при передаче слайса.** `sum(nums)` вместо `sum(nums...)` — ошибка: `cannot use nums (variable of type []int) as int value`.
4. **Затенить именованный результат.** `n := 2` внутри блока создаёт новую переменную (помните затенение из урока 2?). Если после этого написать голый `return`, компилятор откажется: голый return вернул бы *внешнюю* `n`, а это почти наверняка не то, что вы имели в виду.
5. **`missing return`.** Если у функции есть результат, каждый путь выполнения должен заканчиваться `return` — даже если «туда никогда не дойдёт».
6. **`os.Exit` внутри функций с логикой.** Функция, которая сама завершает программу, не годится для повторного использования и тестов. Правило: функции с логикой **возвращают ошибку**, а решение «печатать и выходить» принимает только `main`. `fail` — исключение, потому что это помощник именно для `main`.

### 2. Статистика

Утилита считает статистику по числам из аргументов:

```
$ go run . 3 4.5 10
количество: 3
сумма: 17.50
среднее: 5.83
мин: 3.00, макс: 10.00
$ go run . -2 7
количество: 2
сумма: 5.00
среднее: 2.50
мин: -2.00, макс: 7.00
$ go run .
ошибка: нужно хотя бы одно число
$ go run . 1 abc 3
ошибка: "abc" — не число
```

Требования:
- `parseNumbers(args ...string) ([]float64, error)` — разбирает **все** аргументы; на первом неправильном возвращает ошибку с текстом из примера (`fmt.Errorf`);
- `stats(nums ...float64) (sum, avg, lo, hi float64)` — с **именованными** результатами;
- `parseNumbers` и `stats` не печатают ничего и не вызывают `os.Exit`;
- `parseNumbers` вызывается с `os.Args[1:]` — это слайс аргументов без имени программы. Как передать слайс в вариативную функцию, вы уже знаете;
- вывод — символ в символ, проверка через `check.sh`.

Подумайте: что сделает ваша `stats`, если её вызвать без аргументов? Это нормально или нужно защищаться?
