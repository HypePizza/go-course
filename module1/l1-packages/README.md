# Урок 1. Модуль, пакеты, импорты и `main`

> Модуль 1 «Старт» · Go 1.27.1 · macOS

## Зачем это нужно

Любая программа на Go — от маленькой утилиты до микросервиса — устроена одинаково: **модуль**, внутри него **пакеты**, точка входа — функция `main`. В рабочем проекте на сотни файлов вы постоянно будете разбираться, какой пакет что импортирует и что из него видно снаружи.

## Объяснение

### Модуль

**Модуль** — это ваш проект. Он описывается файлом `go.mod`, где записаны имя модуля и версия Go. Ближайшие аналоги — `requirements.txt` в Python или Makefile в C, но `go.mod` встроен в сам язык.

```bash
mkdir hello && cd hello
go mod init hello
```

Появится `go.mod` со строками `module hello` и `go <ваша версия>`.

В реальных проектах модуль называют по адресу репозитория, например `github.com/yourname/hello`. Пока хватит простого `hello`.

### Пакет

**Пакет** — это папка с `.go`-файлами. Все файлы в одной папке принадлежат одному пакету. Особый пакет `main` с функцией `main()` — точка входа исполняемой программы.

Структура проекта:

```
hello/
├── go.mod
├── main.go
└── greet/
    └── greet.go
```

**`greet/greet.go`**

```go
package greet

import "fmt"

// Hello начинается с заглавной буквы — видна из других пакетов
func Hello(name string) string {
	return fmt.Sprintf("Привет, %s!", decorate(name))
}

// decorate начинается со строчной буквы — приватная функция пакета
func decorate(name string) string {
	return "*" + name + "*"
}
```

**`main.go`**

```go
package main

import (
	"fmt"
	"os"

	"hello/greet" // свой пакет: имя модуля + путь к папке
)

func main() {
	// os.Args[0] — путь к программе, дальше идут аргументы командной строки
	name := "мир"
	if len(os.Args) > 1 {
		name = os.Args[1]
	}
	fmt.Println(greet.Hello(name))
}
```

> `:=` и `if` подробно разберём в следующих уроках. Пока достаточно знать, что `:=` объявляет переменную.

### Запуск и сборка

```bash
go run .            # скомпилировать во временную папку и сразу запустить
go run . Анна       # то же, с аргументом
go build            # собрать бинарник hello в текущей папке
./hello Анна        # → Привет, *Анна*!
```

## Сравнение с C и Python

| | C | Python | Go |
|---|---|---|---|
| Сборка | `gcc`, `.h`-файлы, линковка вручную | интерпретатор, сборки нет | `go build` сам находит пакеты и собирает **один статический бинарник** |
| Запуск на другой машине | нужны совместимые библиотеки | нужен интерпретатор | копируете бинарник — и всё |
| Скрыть функцию | `static` | `_name` — только договорённость | строчная первая буква, **компилятор следит** |
| Заголовочные файлы | есть | нет | нет: пакет импортируется целиком, обращение через имя: `greet.Hello` |

## Типичные ошибки

1. **Неиспользуемый импорт или переменная — ошибка компиляции.** В C это предупреждение, в Python вообще ничего. Раздражает поначалу, зато код остаётся чистым.
2. **`{` на новой строке.** Привычка из некоторых стилей C — в Go это синтаксическая ошибка: компилятор сам расставляет `;` в конце строк. Скобка всегда на той же строке, что `func` или `if`.
3. **`go run main.go`, когда в пакете несколько файлов.** Остальные файлы не попадут в сборку, получите `undefined`. Пишите `go run .`.
4. **Запуск без `go mod init`.** Получите ошибку вида `cannot find main module`.
5. **Ручное форматирование.** Отступы в Go — табы, форматирует `gofmt`. Включите форматирование при сохранении в редакторе (VS Code + расширение Go или GoLand) и не спорьте с ним.

## Задания

### 1. Разминка
Соберите проект из урока, запустите через `go run .` и через бинарник. Затем добавьте в `main.go` импорт `"strings"`, не используя его. Запишите текст ошибки компилятора.

### 2. Свой пакет
Создайте пакет `calc` с экспортированной функцией `Sum(a, b int) int` и неэкспортированной `abs(x int) int`. Вызовите `calc.Sum` из `main`. Затем попробуйте вызвать `calc.abs` — запишите ошибку и объясните своими словами, почему так.

### 3. Посложнее
Сделайте так, чтобы программа печатала, под какую ОС и архитектуру она собрана, например `darwin/arm64`. Нужный пакет найдите сами на [pkg.go.dev](https://pkg.go.dev/std) — он входит в стандартную библиотеку. Потом соберите программу **под Windows**, не выходя из macOS, и посмотрите, что скажет команда `file` о получившемся файле.  
(GOOS=windows GOARCH=amd64 go build -o myapp.exe)
