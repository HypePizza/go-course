## Задача: `hsize` — размеры файлов в человеческом виде

Утилита, которая делает то же, что флаг `-h` у `ls -lh` и `du -h`: переводит байты в удобные единицы и обратно. Пригодится в любом CLI или сервисе, где показывают размеры файлов, лимиты загрузки или занятое место.

**Режим 1 — байты → удобные единицы** (один аргумент, целое число байт). Выбирается **самая крупная** единица, в которой значение не меньше 1:

```
$ go run . 512
512 B
$ go run . 1536
1.50 KB
$ go run . 3500000
3.34 MB
$ go run . 1073741824
1.00 GB
```

**Режим 2 — число с единицей → байты** (два аргумента). Число может быть дробным, единица — в любом регистре, дробная часть байт отбрасывается:

```
$ go run . 1.5 GB
1610612736 B
$ go run . 2 kb
2048 B
$ go run . 0.3 KB
307 B
```

**Ошибки:**

```
$ go run . abc
ошибка: "abc" — не целое число байт
$ go run . -5
ошибка: размер не может быть отрицательным
$ go run . 10 XB
ошибка: неизвестная единица "XB", нужна B, KB, MB, GB, TB или PB
$ go run .
использование:
  go run . <байты>              → в удобные единицы
  go run . <число> <единица>    → в байты
```

Сообщение об использовании печатается и при пустом вызове, и при лишних аргументах (`go run . 1 2 3`).

**Требования**
- Вывод должен **точно** совпадать с примерами — символ в символ.
- Единицы `B`, `KB`, `MB`, `GB`, `TB`, `PB` (1 KB = 1024 B) — константы через **`iota`**, одним блоком. Ни одного «магического» `1024` или `1048576` в коде.
- Выбор режима — через `switch` по количеству аргументов.
- Выбор единицы в обоих режимах — через `switch`. Подумайте, в каком порядке идут `case` в режиме 1 (вспомните FizzBuzz).
- Дробные числа разбирает функция из пакета `strconv`, перевод в верхний регистр — функция из пакета `strings`. Найдите их сами.
- Ошибки — в stderr, код выхода `1`.
- Перед отправкой прогоните **все** случаи из примеров одной командой и проверьте вывод через `cat -e`.
